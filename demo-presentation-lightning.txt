THE FIVE KEY FUNCTIONS / RULES
-------------------------------------------
1. Double-booking blocked in the DB
   supabase/appointments-no-overlap.sql:27
   EXCLUDE USING gist (user_id with =, 30-min tstzrange with &&).
   The database, not the app, enforces the rule.

2. Row Level Security on every table
   supabase/patients.sql:21 and supabase/appointments.sql:28
   Four policies per table: auth.uid() = user_id. The insert policy re-checks
   the patient FK through RLS too (appointments.sql:36).
   Automated proof: tests/rls-isolation.spec.ts:4

3. Charts are Postgres views with security_invoker
   supabase/patients_per_month.sql:5 and supabase/appointment-status-view.sql:4
   Aggregation in SQL, respects the caller's RLS.

4. Server Actions, one validated mutation path
   app/lib/actions.ts: createAppointment (40), createPatient (224),
   setAppointmentStatus (127), updateAppointment (77).
   Zod -> DB -> revalidatePath -> redirect. Works without JS.
   Double-booking error: PG 23P01 mapped to a friendly message at line 67.

5. Live slot picker
   app/ui/appointments/datetime-picker.tsx:27 and 76
   buildTimeSlots (clinic hours 08:00-17:30), isBookedSlot.
   Taken slots from the live DB: app/lib/supabase-data.ts:112
   fetchAppointmentSlotTimes.
